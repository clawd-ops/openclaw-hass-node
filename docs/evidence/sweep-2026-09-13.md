### FAIL -- ha.list_entity_registry

```
COMMAND_ERROR: Message size 7579915 exceeds limit 4194304
WSMessageTypeError: WSCloseCode.MESSAGE_TOO_BIG
```

Entity registry response is 7.6 MB, over aiohttp's default 4 MiB WebSocket ceiling.
Fix location: `openclaw_node/ha_client.py:255`. Tracked in GitHub issue.

### FAIL -- gateway convenience-tool/node command-name mismatch

Gateway `dir_list` and `file_fetch` MCP tools call `dir.list` / `file.fetch`, but the
hass linux-family node advertises `fs.list` / `fs.read`. The convenience tools cannot
reach those commands by those names. Direct `fs.list` and `fs.stat` node invocations
pass, so the defect is the gateway tool-name mapping rather than the `fs.*` surface.
Tracked in GitHub issue.

### VALIDATION ONLY

`fs.diff` reached the node for `/config/configuration.yaml` with `from_version=-1`, then
returned `DIFF_ERROR` because no backup versions were recorded. Dispatch and validation are
production-live; successful diff rendering remains unverified.

`ha.config.lovelace#get` reached Home Assistant but returned `HA_CONFIG_NOT_FOUND` because
this installation uses YAML mode. Dashboard and resource listing both passed.

### FAIL

`ha.config.entity_registry#list` returned `COMMAND_ERROR: Internal command error` on the
7,217-entity installation. The related large-registry failure is tracked in issue #316.

Direct `ha.list_states` silently accepted but ignored `entity_filter`, returning the full
5.36 MB state set. The Assist wrapper applied the same conceptual filter correctly.

### REFUSED ON THIS PATH

`system.execApprovals.get` is advertised by the node, but direct node invocation returns
`INVALID_REQUEST` and directs the caller to `exec.approvals.node.*`.

Ruled in #333: this is intended gating, and the advertisement is correct as well. The
command keeps its place in the advertised list and in `gateway.nodes.commands.allow`,
because that pair is what lets the Gateway forward it on the operator surface that does
reach it. `system.run` has the same shape and was already documented that way. Nothing
about the surface changed; the reachability contract is now written down in
`docs/reference/COMMAND-SURFACE.md`.

### Still excluded

All commands that mutate state remained unprobed, including filesystem writes, service
calls, add-on lifecycle/update operations, `ha.update_install`, and mutating
`ha.config.*` actions.
