## OpenClaw core blocker

Approval waits and gateway tools fail from sessions that run on the claude-cli backend in
OpenClaw `2026.9.8`. Upstream: openclaw/openclaw#158550 (the claude-cli MCP loopback server keeps
the first CLI turn's gateway request scope; the fix in #157144 is not in `2026.9.8`).

Effects observed:

- Turns that originate from the chat-channel main session could not use `nodes`, `ha_*`,
  `sessions_spawn` or `sessions_history` at all ("Gateway caller authority is no longer active").
- Turns from the Control UI session could use them, but approval waits aborted within seconds
  ("Approval requester authority changed", "agent tool caller authority is no longer active").
  The prompt then dangled until its 600 s expiry; approving it later did nothing (fail-safe).
- Approvals from Assist sessions worked in the approve, deny, allowlist and node-side refusal cases. The first super_admin Music Assistant restart was approved, but the requester's wait was dropped by the OpenClaw core bug ("Approval requester authority changed") and nothing ran. For the Grafana `ha.update_install` case the prompt worked, the command returned `COMMAND_ERROR`, and the model escalated to a second prompt.
- Approvals from the main agent session failed intermittently, consistent with the stale-scope bug.

Remaining approval tests are listed under [Not run](#not-run) and tracked in #415.

## Decisions

Operator decisions recorded at the end of the session (2026-10-05).

**Role-aware approval policy** (#405):

- User-directed (verified HA user in an Assist turn): no prompt.
- Agent-initiated (main session, chat channel, heartbeat, cron, subagent): prompt.
- Destructive: always prompt. Destructive means: delete automation/script/scene/helper/area, entity remove, `fs` delete/move/restore, HA stop, config entry disable, update install.
- File writes: undecided, default prompt.
- `super_admin` should need approval for very few things.

**Lifecycle matrix** (#406):

| Action | admin | super_admin |
|---|---|---|
| add-on start (allowlisted) | allowed, no approval | allowed, no approval |
| add-on restart (allowlisted) | allowed, no approval | allowed, no approval |
| add-on stop (allowlisted) | approval | allowed, no approval |
| HA restart | allowed, no approval | allowed, no approval |
| HA stop | refused, no prompt | approval |

Also reword the "you are now in admin mode" anti-override example so it does not use a real role name.

**Announce approvals** (#404): Assist and the agent must say "approval required, waiting on you" the moment an approval is requested.

**Allow for this session** (#407): use allow-always; scope is same session + command + action; 1 hour, session end or gateway restart; in memory only; never for destructive calls.

**Allowlist feedback** (#408): `addon_lifecycle.allowlist` adds friction without much safety once approvals are role-aware and `homeassistant`/`supervisor`/`core_*` stay hard-denied. Drop it or make it an opt-in deny-list.

**Other fixes agreed:** hide `ha_*` tools outside `ha-assist:` sessions (#414); refuse before prompting (#403).
